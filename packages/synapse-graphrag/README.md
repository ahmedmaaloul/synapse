# synapse-graphrag

**MCP server, CLI and async Python client for [Synapse](https://github.com/ahmedmaaloul/synapse) — budgeted GraphRAG context for any LLM host.**

Synapse turns PDFs into a Neo4j knowledge graph (entities, relationships, Louvain
communities with LLM summaries, source excerpts) and answers questions with GraphRAG.
This package is the *client side*: it lets Claude Code, Claude Desktop, Cursor, VS Code,
Windsurf — or any Model Context Protocol host, or a plain Python script — query that
graph over HTTP.

The headline tool is **`synapse_retrieve`**: it returns graph context cut to a character
budget and lets *your* model write the answer. No second generation call, no second bill.

```text
┌──────────────┐   MCP (stdio / HTTP)   ┌────────────────┐   HTTP   ┌──────────────────┐
│ Claude, Cursor│ ─────────────────────▶ │ synapse-graphrag│ ───────▶ │ Synapse backend  │
│ VS Code, …    │ ◀───────────────────── │ (this package)  │ ◀─────── │ FastAPI + Neo4j  │
└──────────────┘  context + citations    └────────────────┘          └──────────────────┘
```

Requires a running Synapse backend (`make up` in the repo, default `http://localhost:8000`).

## 60-second install

The server runs from PyPI with [`uv`](https://docs.astral.sh/uv/) — nothing to clone.
`synapse-graphrag install-config --client <name>` prints the exact snippet for each host.

**Claude Code**

```bash
claude mcp add synapse -e SYNAPSE_URL=http://localhost:8000 -- uvx synapse-graphrag mcp
```

**Claude Desktop** — `claude_desktop_config.json` (macOS: `~/Library/Application Support/Claude/`, Windows: `%APPDATA%\Claude\`), **Cursor** — `~/.cursor/mcp.json` or `.cursor/mcp.json`, **Windsurf** — `~/.codeium/windsurf/mcp_config.json`:

```json
{
  "mcpServers": {
    "synapse": {
      "command": "uvx",
      "args": ["synapse-graphrag", "mcp"],
      "env": { "SYNAPSE_URL": "http://localhost:8000" }
    }
  }
}
```

**VS Code** — `.vscode/mcp.json`:

```json
{
  "servers": {
    "synapse": {
      "type": "stdio",
      "command": "uvx",
      "args": ["synapse-graphrag", "mcp"],
      "env": { "SYNAPSE_URL": "http://localhost:8000" }
    }
  }
}
```

**Any streamable-HTTP client** — run the server once, point clients at `http://127.0.0.1:8765/mcp`:

```bash
pipx install synapse-graphrag        # or: pip install synapse-graphrag
synapse-mcp --transport streamable-http --host 127.0.0.1 --port 8765
```

**Docker** — from the Synapse repo, `docker compose --profile mcp up -d` starts the
`synapse-mcp` container next to the backend and publishes `http://localhost:8765/mcp`.
The image is also built from `packages/synapse-graphrag/Dockerfile` with the repo root
as context (`docker build -f packages/synapse-graphrag/Dockerfile -t synapse-mcp .`).

## Tools

| Tool | What it does | Hints |
| --- | --- | --- |
| `synapse_retrieve` | GraphRAG context for a question, cut to `max_context_chars`, with citations, reasoning paths, source excerpts and `usage`. **No LLM call on the backend.** | read-only, idempotent, cached |
| `synapse_ask` | A complete answer generated by the backend's own LLM (streams aggregated). Costs a **second** LLM call. | read-only |
| `synapse_ingest_pdf` | Ingest a local PDF: parse → extract → embed → write → re-detect communities. Returns the job summary. | writes, not destructive |
| `synapse_communities` | The corpus' themes: Louvain communities with LLM titles and summaries. | read-only |
| `synapse_find_entities` | Case-insensitive substring search over entity names and types, best-connected first. | read-only |
| `synapse_graph_stats` | Node/edge counts, entities per type, relationships per type, top entities. | read-only |
| `synapse_status` | Health, readiness (Neo4j), version and providers of the backend. | read-only |
| `synapse_clear_graph` | Delete the whole graph. **Refuses unless `confirm=true`.** | destructive |

Plus one resource, `synapse://about` (backend metadata as JSON), and two prompts. The first,
`answer_with_graph(question)`, instructs the model to call `synapse_retrieve`,
answer only from the context, cite entity names, and say when the graph lacks the answer.
The second, `safety_brief(topic)`, turns a topic into a structured, cited
AI-safety brief (claims · evidence labelled demonstrated / hypothesised · mitigations and
their evaluation status · open questions · not in the corpus) for corpora ingested with the
`AI Safety` theme — see `docs/ai-safety.md` in the repository.

Errors are readable sentences, never tracebacks: a backend that is down yields
`Cannot reach Synapse at http://localhost:8000: … Is it running? (\`make up\`)` as an
`is_error` tool result.

## FinOps: budgeted context, not a second LLM bill

A GraphRAG answer normally costs two model calls — one to *generate* on the backend, and
one in the host that reads it. `synapse_retrieve` removes the first:

- **`max_context_chars`** caps the context the host has to pay for. The backend cuts on a
  line boundary and marks the result with `usage.truncated`. The default budget comes
  from `SYNAPSE_MAX_CONTEXT_CHARS` (6000; `0` disables it, otherwise at least 200 — the
  backend's floor).
- **`usage`** on every response — `context_chars`, `context_tokens_est` (≈ chars / 4),
  `truncated`, `citations`, `paths`, `sources`, `cached` — so an agent can account for what
  it spent and decide whether to retrieve again with a larger budget.
- **TTL cache**: identical `(query, k, budget)` calls within `SYNAPSE_CACHE_TTL` seconds
  (300 by default) are served in-process with `usage.cached: true`. Agents re-ask the same
  question several times per task; only the first one touches the backend.
- **`synapse_ask`** stays available when you *want* Synapse's own answer — its description
  says it costs a second call, so hosts pick it deliberately.

From the CLI: `synapse-graphrag retrieve "…" --budget 2000 --json`.

## CLI

```text
synapse-graphrag [--url URL] [--version] COMMAND

  status                      health, readiness, version and providers
  ask QUERY                   stream a grounded answer (backend LLM)
  retrieve QUERY [--k N] [--budget CHARS] [--json]
                              print GraphRAG context, no generation
  ingest FILE.pdf [--theme T] ingest a PDF with live progress lines
  communities [--limit N]     list the corpus' themes
  stats                       node/edge counts and type breakdowns
  mcp [--transport stdio|streamable-http] [--host H] [--port P]
                              run the MCP server (same as `synapse-mcp`)
  install-config --client {claude-code,claude-desktop,cursor,vscode,windsurf} [--url U] [--budget N]
                              print the config snippet / command for a host
```

Every command exits `1` with a one-line `error: …` on stderr when the backend is
unreachable or answers with an error; machine-readable output (`retrieve --json`,
`install-config`) goes to stdout alone.

## Python client

```python
import asyncio
from synapse_graphrag import SynapseClient

async def main() -> None:
    async with SynapseClient("http://localhost:8000") as client:
        retrieval = await client.retrieve("Who designed the Analytical Engine?", k=8, max_context_chars=2000)
        print(retrieval.mode, retrieval.usage)          # 'local' {'context_chars': …, 'truncated': …}
        print(retrieval.context)                        # feed this to your own model
        for c in retrieval.citations:
            print("-", c["name"], c["type"])

        answer = await client.ask("Summarise the graph")  # backend LLM; raises SynapseError on failure
        result = await client.ingest_pdf("paper.pdf", theme="Research", on_progress=print)
        print(result.nodes_created, result.relationships_created, result.communities)

asyncio.run(main())
```

`SynapseClient` also exposes `health()`, `ready()`, `about()`, `ask_stream()` (raw SSE
events), `graph()`, `communities(limit)`, `rebuild_communities(on_progress)` and
`clear_graph()`. All failures raise `SynapseError(status, detail)`; an unreachable backend
raises the `SynapseConnectionError` subclass.

## Environment variables

| Variable | Default | Meaning |
| --- | --- | --- |
| `SYNAPSE_URL` | `http://localhost:8000` | Backend base URL (`--url` overrides it). |
| `SYNAPSE_API_KEY` | — | If set, sent as `Authorization: Bearer …`. The open-source backend ignores it; an authenticating proxy in front of it will not. |
| `SYNAPSE_TIMEOUT` | `120` | Per-request timeout in seconds (also the idle timeout between SSE events). |
| `SYNAPSE_MAX_CONTEXT_CHARS` | `6000` | Default budget for `synapse_retrieve` and `retrieve --budget`; `0` disables the budget; positive values below 200 (the backend's floor) are rejected. |
| `SYNAPSE_CACHE_TTL` | `300` | Seconds identical retrievals are served from the cache; `0` disables it. |

## Security

The Synapse backend has **no authentication** of its own. Keep it on localhost, a private
network or a VPN, or put it behind an authenticating reverse proxy (Caddy, nginx, Traefik,
an API gateway) — `SYNAPSE_API_KEY` exists so this package can present a bearer token to
such a proxy. The same applies to the MCP server over streamable HTTP: bind it to
`127.0.0.1` unless something in front of it authenticates callers.

`synapse_clear_graph` and `synapse_ingest_pdf` change the graph; hosts show their
`destructiveHint` / `readOnlyHint` annotations so users can grant them deliberately.
